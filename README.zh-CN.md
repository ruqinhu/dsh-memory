# @ruqinhu/dsh-memory

[English](README.md) | 中文

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的长期记忆：
两份 `§` 分隔的文档、一个硬性字符预算，以及让索引可跳转的内容派生 ID。

## 1. 约束

| 约束 | 后果 |
| --- | --- |
| 记忆是提示上下文，每次请求都付费 | 两份文档都有硬性上限 |
| 被截断的规则等于被悄悄丢掉的规则 | 超限写入**拒绝**，绝不截断 |
| 上限逼着必须删 | 删要有证据，所以统计用量 |

| 文档 | 默认上限 | 存什么 |
| --- | --- | --- |
| `MEMORY.md` | 2,200 字符 | 长期规则 |
| `USER.md` | 1,375 字符 | owner 画像与长期偏好 |

反面案例：参照的 Hermes 部署涨到 3,687/2,200（超 68%）与 2,748/1,375（超 100%），无人察觉。

## 2. 机制

| 问题 | 决定 | 否决的替代 | 代价 |
| --- | --- | --- | --- |
| 注入多少 | 合计 ≤ 6,000 字符整份内联；超过则只注入索引（ID + 首行） | 一直内联会挤占工作上下文；一直索引让小部署白付一次往返 | 索引模式多一次工具调用 |
| 条目叫什么 | ID = hash(目标, 正文) 取十位十六进制，前缀 `m-`/`u-` | 位置编号（`第 7 条`）每次压缩都重排，旧引用静默指向别的规则 | 规则被改则 ID 失效（有意） |
| 怎么读回一条 | `memory_get(id)`；`memory_search` 也返回 ID | 只给 80 字首行：想读完全文只能猜关键词 | 多一个工具 |
| 中文怎么匹配 | 二元组（`止损怎么设` → `止损`/`损怎`/`么设`），ASCII 词 ≥2 字符 | 整段保留：`止损怎么设` 对 `止损 2.96` 得 **0 分**，召回静默为空 | 单字仍不切（太宽泛） |
| 召回注入多少 | 1,500 字符预算，高分优先，放不下的条目**跳过** | 截断：半条规则读起来像完整的 | 某条太大时可能一条都放不下 |
| 用量证据在哪 | 侧车 `.entry-index.json`：`hits`、`firstSeenAt`、`lastHitAt` | 凭感觉压缩：删掉仍有效的、留下死规则 | 内联注入的条目永不计数 —— 证据只是下界 |
| 何时算「没用」 | 维护报告列出 45 天未命中、年龄 ≥14 天、最多 12 条，按字符数降序 | 全量列出：没人读的清单 | 是抽样，不是清单 |
| 写作纪律放哪 | `memory-curation` 技能，仅当 profile 有技能注册表时注册 | 每请求注入协议：用上下文讲「怎么写上下文」 | 没有注册表就没有技能 |

注册走延迟子 fiber（`ctx.inject(['skills'])`），不是 `static inject` —— 把注册表写成必需依赖，
会让没有它的 profile 整个插件都加载不起来。

## 3. 失败模式

| 失败 | 现在的行为 |
| --- | --- |
| 写入超上限 | 拒绝并报当前值/上限，逼一次压缩 |
| 对过期 ID 调 `memory_get` | 回答「请调用 `memory_search`」，而不是解析成另一条规则 |
| 召回抛错 | 吞掉；召回失败绝不让回合失败 |
| profile 没有技能注册表 | 跳过注册，插件照常加载 |
| 侧车文件损坏 | 当空处理，下次同步从文档重建 |
| 自动召回每回合触发 | 侧车写入合并为每分钟最多一次 |

## 4. 实测

| 项 | 结果 |
| --- | --- |
| 单测 | 118 个、15 个文件；`tsc --noEmit` 在 `strict` 下干净 |
| 线上往返 | `memory_search("网关")` → `m-efa7252010`；`memory_get` 拿回完整 95 字条目；`hits` 到 2 |
| 技能注册 | 线上 agent 的技能目录里有 `memory-curation` |
| 线上形态 | 38 条条目、上限调到 3,000 字符，仍在 6,000 内联阈值内 |

## 5. 开放问题

| 问题 | 现状 |
| --- | --- |
| 自动召回 | 默认关；只有注入转为索引后才有价值 |
| `snapshot()` | 返回活记录而非副本，命名误导；测试通过它改状态 |
| 冷清单 | 12 条抽样，不是清单 |
| 改写条目 | 统计清零（有意，但藏掉用量历史） |
| 跨文档重复 | 不检测；同一规则出现在两份文档算两条 |
| 上限单位 | 字符而非 token —— 换语言要重新量 |
| 跨设备共享 | 无，也没有加锁方案 |

## 6. 兼容性

| 项 | 值 |
| --- | --- |
| DSH | `0.2.1-rc.5`（peer 依赖按此钉住） |
| 运行时 | Node 22+，无原生模块 |
| 运行时依赖 | 只有 `@deepseek-ai/schemastery` |
| 可选集成 | `@deepseek-ai/dsh-skill` —— 缺失只是没有技能，不是插件不加载 |

## 7. 安装与配置

```bash
dsh plugin add @ruqinhu/dsh-memory
```

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `memoryCap` | `2200` | `MEMORY.md` 上限 |
| `userCap` | `1375` | `USER.md` 上限 |
| `enableInjection` | `true` | 是否作为动态上下文注入 |
| `backupKeep` | `12` | 保留的备份目录数 |
| `memoryDir` | `~/.dsh/memory` | 文档与备份目录 |
| `enableRecall` | `false` | 是否注册 `memory_recall` |
| `enableAutoRecall` | `false` | 是否每回合自动召回 |
| `recallBudgetChars` | `1500` | 单次召回上限 |
| `staleAfterDays` | `45` | 多久未用算冷条目 |
| `staleMinAgeDays` | `14` | 年轻于此天数永不报为未使用 |
| `enableSkill` | `true` | 有注册表时注册 `memory-curation` |

## 8. 工具

| 工具 | 用途 |
| --- | --- |
| `memory_read` | 读文档，含用量与条目数 |
| `memory_get` | 按 ID 读单条全文 |
| `memory_search` | 关键词检索，返回带 ID 的得分结果 |
| `memory_recall` | 检索并排版成可直接使用的块（`enableRecall`） |
| `memory_write` | 整体替换（超上限拒绝） |
| `memory_append` | 追加一条（超上限拒绝） |
| `memory_replace` | 精确替换子串 —— 压缩原语 |
| `memory_maintenance` | 备份、轮转、报告用量、列冷条目 |

每周维护：把定时任务指向 `memory_maintenance`，再用 `memory_replace` 合并或删除条目，直到
用量回到上限内。
